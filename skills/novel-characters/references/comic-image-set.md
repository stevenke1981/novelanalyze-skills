# 漫畫版圖片組製作規格

完成 `cast.json` 後，預設同時建立漫畫版與真人版圖片組。不要把既有 `image.prompt` 直接當成完整漫畫製作包；角色卡裡的卡通欄位維持相容，漫畫製作設定使用獨立 sidecar。

## 成果

至少交付：

- `<書名>-comic.json`：完整漫畫身份鎖定、全案視覺聖經、鏡頭組與逐張狀態。
- `<書名>-comic.md`：方便漫畫／分鏡團隊閱讀與複製提示詞的版本。
- `images/comic/<slug>/*.png`：只有實際生成成功時才交付。

資料結構見 `comic-schema.md` 與共用欄位說明 `live-action-schema.md`。確定性工具：

```bash
node "<SKILL_DIR>/scripts/comic-image-set.mjs" validate "<書名>-comic.json" "<書名>-cast.json"
node "<SKILL_DIR>/scripts/comic-image-set.mjs" render "<書名>-comic.json" --md > "<書名>-comic.md"
node "<SKILL_DIR>/scripts/comic-image-set.mjs" audit "<書名>-comic.json" "<輸出目錄>" "<書名>-cast.json"
```

## 工作順序

1. 先完成並驗證 `cast.json`。漫畫設定必須以角色卡中的原文依據、外貌、性格與服裝為來源。
2. 建立一份全案共用的漫畫 `styleBible`，只定義一次時代、地域、線條、分鏡、限色與連戲規則。
3. 為每位要漫畫化的角色建立 `identityLock`。預設處理 `protagonist` 與 `major`；使用者要求全部時才擴大。
4. 建立七張必要圖片設定：身份固定板、中性立繪、臉部角度組、全身三視圖、表情九宮格、服裝道具板、分鏡關鍵畫面。
5. 執行 `validate`，修正到結束碼為 0。
6. 若有圖像工具，**先只生成 `identity-board`**。確認它合格後，才可作為其餘六張的主參考圖。
7. 後續每張都同時帶入核准的身份固定板、相同 `basePrompt`、相同角色反向提示詞與相同服裝連戲規格。
8. 每張圖片完成後更新 `status`：`PASS`、`FAIL` 或 `NOT_RUN`。只有檔案存在、可開啟且通過驗收時才能標示 `PASS`。
9. 執行 `audit` 比對狀態與實際檔案，再產生 Markdown。

## 身份硬鎖定

下列屬性是不可隨分鏡變動的硬性約束：

- 臉型比例、顴骨、臉頰、下頜與下巴。
- 眼睛輪廓、眼距、眼瞼與視線氣質。
- 眉毛弧度、粗細、顏色與眉眼距離。
- 鼻樑、鼻尖、鼻翼與側臉輪廓。
- 上下唇厚度、唇峰、嘴角。
- 髮際線、分線、瀏海、髮色、髮長與固定髮型結構。
- 身高、肩寬、軀幹比例、四肢比例與慣常姿態。
- 主要服裝的版型、色塊、配件與道具細節。
- 全案統一的線條粗細、色面分層與印墨質感。

可變屬性只有表情、姿勢、分鏡構圖、場景走位與有動機的光影強弱。若故事需要換裝、受傷、年齡變化或髮型變化，必須另建明確命名的狀態版本，不得靜默改動基礎身份。

## 七張必要圖片

| ID | 中文名稱 | 比例 | 用途 |
| --- | --- | --- | --- |
| `identity-board` | 漫畫角色身份固定參考圖表 | 16:10 | 核准臉、身形、髮型、服裝與線條；是其他圖片的主參考 |
| `neutral-portrait` | 漫畫中性立繪 | 4:5 | 最乾淨的胸上立繪，供臉部一致性比對 |
| `face-angles` | 漫畫臉部角度組 | 16:10 | 正面、四分之三、側面等角度核對輪廓 |
| `full-body-turnaround` | 漫畫全身三視圖 | 16:10 | 正、側、背並排，核對比例與服裝連戲 |
| `expression-grid` | 漫畫表情九宮格 | 16:10 | 只改表情與視線，不改身份 |
| `wardrobe-board` | 漫畫服裝與道具板 | 16:10 | 核對色塊、線條、磨損符號與道具 |
| `cinematic-keyframe` | 漫畫分鏡關鍵畫面 | 16:9 | 將核准人物放入故事分鏡，驗證表演與場景一致性 |

## 提示詞組合

每張實際交給圖像工具的內容依序組合：

1. `styleBible.realityLevel` 與 `styleBible.capture`。
2. 該角色的 `basePrompt`。
3. 該圖片的 `shot.prompt`。
4. 「以核准身份固定板為最高優先參考」的連戲指令。
5. `styleBible.globalNegativePrompt`、`characterNegativePrompt` 與 `shot.negativePrompt`。

英文提示詞與中文提示詞中都不得出現角色名、別名、作者名、作品名、演員名、明星名或公眾人物名。描述可觀察特徵，不靠名字喚起模型記憶。

## 產圖原則

- 不要一次用純文字獨立生成七張。先核准身份固定板，再以同一張參考圖逐張生成。
- 工具支援參考圖權重時，身份參考設為高；服裝參考至少為中高。
- 工具支援 seed 時可重用，但 seed 不能取代身份參考圖。
- 不使用「像某部漫畫／某個角色」作為捷徑，避免授權與身份漂移問題。
- 不把真人寫實、照片、3D 模型、塑膠皮膚或過度萌化當成這套漫畫規格。
- 圖像工具不可用時，完整交付 JSON、Markdown 與提示詞，所有圖片維持 `NOT_RUN`。

## 單張驗收

每張至少檢查：

1. 是否與核准身份固定板為同一人。
2. 臉型、眼距、鼻形、唇形、髮際線有無漂移。
3. 身高、肩寬、四肢比例與服裝色塊是否連戲。
4. 是否符合該張圖片的構圖、背景、比例與功能。
5. 是否有多手指、肢體融合、文字碎片、浮水印或突然變成真人照片。

`identity-board` 未通過時，後續圖片一律不可開始。單張失敗不阻斷文字成果，但最終必須清楚列出 `FAIL` 與 `NOT_RUN`。

`audit` 對 `PASS` 會檢查：檔案存在、非空、是有效 PNG、長寬比符合該張 `aspectRatio`，並在可解碼時把後續圖與 `identity-board` 做平均雜湊比對。純文字假檔不能再標 `PASS`。可選序列生成見 `sequence-generation.md`；參考圖模型見 `optional-ip-adapter.md`。
